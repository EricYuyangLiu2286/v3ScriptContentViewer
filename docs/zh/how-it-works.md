# 工作原理

## 1. 数据层与文件

配置按加载顺序给出游戏和各 MOD，每个成为一层：`game`、`mod1`、`mod2`……

| 情形 | v3tree 的处理 | 依据 |
|---|---|---|
| 多层有同一相对路径的文件 | 靠后一层的文件整份取代靠前的 | 通行做法；MOD 靠它替换原版文件 |
| 同一文件夹内的文件 | 各层合在一起，按文件名排序读取 | 推定（Jomini 引擎惯例；游戏目录里没有文档） |
| `REPLACE:`、`TRY_REPLACE:`、`REPLACE_OR_CREATE:` | 整条定义被替换；旧位置标“被替换” | Paradox 公开说明；游戏目录里没有文件可证 |
| `INJECT:`、`TRY_INJECT:`、`INJECT_OR_CREATE:` | 合并进原定义，两处都抽边 | 同上 |
| 同名定义、没有前缀 | **先读到的为准**；后一处标“忽略”并在报告里列为重复 | 未证实。旁证：Community Mod Framework 把覆盖文件命名为 `00_com_…`，让它先于原版读取，这只在“先读到的为准”时才有效 |
| 同名 on_action | 所有定义合并（事件列表累加） | MOD 常在多个文件里各自往 `on_monthly_pulse_country` 添加内容 |
| 本地化 | 后读到的键为准；`localization/<语言>/replace/` 优先于普通文件 | 通行约定 |

## 2. 索引

约 40 个文件夹中的每个定义（日志、事件、决议、按钮、进度条、法律、外交博弈、战争目标、修正、on_action、scripted effect/trigger/value、开局历史、人物模板、政体、政党等）都会被解析并逐层遍历，每处引用成为一条边：

- **调用**：效果、事件选项、结局、按钮效果、`trigger_event`、`random_events`、`add_journal_entry`、scripted effect、写变量、加修正、颁布法律、迁移人口；
- **条件读取**：trigger、`possible`、`is_shown`、`limit`、数值块中读取 JE、变量、法律、scripted trigger、script value；
- **结构**：日志的按钮与进度条。

每条边记录文件、行号（块引用还记结束行）、上下文（“结局2(失败)·效果”“选项3”“每月脉冲 随机 10/220”“延迟5天”）和标记（`tooltip_only`、`disabled`）。

另外处理的情形：

- 参数化 scripted effect：用每个调用点的实参填入 `$PARAM$`，边从调用方出发，并注明调用点。
- 人口：遍历人口时的筛选条件（含其中用到的 scripted trigger）成为“人口对象”；迁移或改变人口即为写入。先把人口存进变量、之后再迁移的写法也算。
- 引号里的内联数值，例如 `"scripted_bar_progress(bar)"`。
- 多行块：`trigger_event = {` 换行 `id = x }` 记为一条跨这几行的边。

不运行游戏就解析不了的（scope 目标、存在变量里的值、没有调用点给出的参数）写进 `unresolved.md`，不猜测。

## 3. 两种出图方式

**判定式（AI 或人，命令行）。** `expand` 列出每个同主题节点尚未判定的全部邻居，在 `decisions.txt` 里逐个判定，直到没有待判定的。准确、可解释，较慢。

**步数搜索（网页界面或 `v3tree search`）。** 从根出发沿引用往外走 N 步。停止规则防止吞进整个游戏：被引用超过 N 处的节点（默认 40）、国家、人物、文化、法律、意识形态、引擎 on_action，以及（加载了 MOD 时）只有原版定义的内容，都只画不往外找。可以接受、只画不展开或去掉节点，然后继续找；验收时，待定节点算同主题，停止规则节点算边界。速度快；边界准不准取决于你的剪枝。

两种方式写同一种判定文件，可以互相接着做。

## 4. 报告

- 索引和子树的数字，涉及本图的未解析引用。
- 软边的确认与剔除，附理由。
- 每条判定及其理由和来源（逐项或规则）。
- **反向检查：** 在脚本原文里搜索每个同主题 id，列出无法由任何边解释的出现。
- **抽查：** 随机 10 条边，回原文件比对。
- **疑似问题：** 只写不读（本地化、GUI 也没显示）的变量、只读不写的变量、没人触发的事件、没人调用的工具、只在 `show_as_tooltip` 里的效果、`always = no` 下的分支。
